## How a ticket runs (the flow that works, and its speed rules)

- **One lane per ticket** with the machine rules above in its prompt; the lane commits its own ticket
  (one conventional commit, paths staged by name, no trailers) and returns: hash, files, exact commands
  with pass/fail counts, each acceptance criterion met/not met, findings outside scope.
- **Adversarial review** of the commit by a second agent (read-only, medium effort): every acceptance
  criterion met by code with a test that would fail otherwise (vacuous tests count as unmet), the
  owner's ruling built as ruled (not narrower/wider), CLAUDE.md conventions, S1–S12 + ADR-0061 tenant
  stamping on every new row path, no PII in audit rows/notes/PDFs, schema change ⇒ one `Initial` regen
  in the same commit + full integration run, no attribution, no ticket ids in source comments, no
  comment the diff made false left standing. Then a fix lane for blockers/majors.
- **Speed rules (owner-approved 2026-09-15):** one review per phase for non-schema, non-money,
  non-security tickets (schema/money/security tickets keep their own); filtered suites inside lanes,
  the full suites once in the main-session verification; small tickets share a lane; verify only the
  stacks a batch touched; reviewers at medium effort.
- Lanes are told: never `git add -A`/`.`/`-a`; if `.git/index.lock` exists, wait 5 s and retry.
