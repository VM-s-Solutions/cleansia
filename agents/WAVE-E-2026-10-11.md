## Local loop measurement (C01–C02)

**Setup.**
- Machine: Apple M4 MacBook Air, 10 cores, 16 GiB, on AC power.
- Toolchain: Node 22.23.3 (the same as hosted CI), npm 10.9.9, Nx 23.2.1, Jest 30.5.0, .NET 10.0.301.
- Source: a clean, dedicated worktree at master `620f3c7`, clean before and after.
- Every cache (Jest transform cache, npm, NuGet, Nx data) was redirected to scratch, so "cold" means an empty directory and real caches were never touched. Spotlight was kept off the scratch folders.

**Method.**
- Runs were serial, three valid runs per cell. Sweep configurations ran round-robin.
- A run counts only if it exits 0 with the exact totals: 74 Jest projects and 5,038 tests, or 8,639 .NET unit tests.
- The 1-minute load had to fall below 3.5 before each run, and each run's load is recorded. This Mac idles near 3, from OS background work and Docker.

### What it shows

- **The web test loop is the cost.** Most of it is Jest's transform and type-check: an empty cache costs 829 s against 242 s warm, at default settings. CI never keeps that cache, so every heavy CI run pays the cold price. That is consistent with the ground truth's heavy-run CI median of about 1,160 s on a 4-vCPU runner.
- **Nx's three tasks each fanning out to (cores − 1) Jest workers oversubscribe the machine.** The load reached 35–47 on 10 cores. Bounding the workers is the largest single lever measured: `--maxWorkers=1` is 63 % faster cold and 60 % faster warm, with non-overlapping ranges and identical counts. That clears T-0809's bar, so it lands as a README recommendation only.
- **Jest's worker-exit warning appears only in the cold, oversubscribed runs.** It is absent from all twelve warm runs and all six bounded ones. That supports T-0810's hypothesis of slow worker exit under load. No handle leak was found.
- **The backend loop has no lever that clears the bar.** Its cold cost is the package download; warm, the unit suite takes about a minute; the README form adds about 4 s.
- **Limits.**
  - A 10-core M4 does not predict a 4-vCPU hosted runner quantitatively.
  - Total memory across processes was not measured.
  - Android, iOS and the container suites were not measured locally; their levers are CI-side.
