# Three-app web responsiveness audit — 2026-09-16

Scope: [T-0767](../backlog/tickets/T-0767-responsiveness-audit-three-web-apps.md). Report only; no application fixes are made by this audit.

All 109 rendered route bindings and 12 redirect bindings were attempted at **400 × 844** and **768 × 1024 CSS pixels**. The results identify **seven layout/control-sizing groups** and **two runtime groups**. The most serious responsive defect is missing partner/admin navigation at exactly 768 px. Admin package edit cannot reach a measurable DOM at either width; five other admin form bindings render with textarea errors. These runtime gaps are recorded, not marked clean.

### R01: the 768 px navigation gap

The shared sidebar CSS uses `@media (max-width: 768px)` to collapse the sidebar container to zero width. Both app shells and the sidebar component use `innerWidth < 768` to select mobile behavior. At exactly 768 px the CSS has removed the desktop navigation space while TypeScript does not render the mobile toolbar. Diagnostic captures in both apps show a 14 px sidebar, zero-width container and no toolbar. At 767 px the toolbar is present; at 769 px the sidebar is 224 px wide. Mobile menus open at 400 px.

### R02–R06: action labels lose their meaning

Thirteen affected label instances occur across seven route/width pairs. Partner GDPR and invoice labels truncate at **both** requested widths. The employee-document, email-translation and raw-JSON actions truncate at 400 px; their corresponding 768 px labels remain readable. Some admin buttons retain only an initial and ellipsis. This is action-label loss even though the document itself fits the viewport.

The shared button stylesheet records the **2026-08-27 owner ruling to use single-line ellipsis instead of wrapping**. The suggested repairs preserve that fallback: give actions sufficient width or stack action controls. Ellipsis itself is not prohibited, and the report does not propose changing the owner’s rule. The constraint is visible in [src/Cleansia.App/libs/shared/assets/src/styles/components/cleansia-button.component.scss:13](../../src/Cleansia.App/libs/shared/assets/src/styles/components/cleansia-button.component.scss#L13) and the responsive `small-width` rules in [src/Cleansia.App/libs/shared/assets/src/styles/common/sizing.scss:106](../../src/Cleansia.App/libs/shared/assets/src/styles/common/sizing.scss#L106).

### R07: shared touch targets

Observed examples include 41 px customer login inputs, 40 px submit/password-eye controls, 35 px partner/admin login inputs, a 32 × 32 px mobile-menu button, a 25 × 25 px open-menu close button and 28 × 28 px admin pagination buttons. Confirm actual hit areas before broad shared-style changes, especially checkboxes and inline links. ## Method, evidence and limitations

The captures use Chromium through the repository’s Playwright dependency, device scale factor 1, Czech locale, Prague timezone and light theme. All browser requests are locally fulfilled or aborted, service workers are blocked, an unreachable proxy prevents network fallback, and API origins are rewritten only in served bundle copies. Fifty-one exact public font/icon assets (3,221,138 bytes) were cached separately for rendering. No real account, backend, external payment provider, map service or SSR execution is represented.

The fixture builder reads generated-client method/path and DTO shapes and applies explicit overrides. Route parameters use synthetic `audit-id` values; local storage supplies synthetic sessions for guarded routes. Responses usually contain one representative row and one Czech market. Query/body semantics are not generally modeled, and recursive/deep or unknown types can become null. Contract-shaped data does not establish domain-valid behavior, authorization or backend correctness. The valid-weight package retry reduces one fixture concern without turning the audit into a backend test.

The baseline runner waits 650 ms after navigation and waits for fonts, bounded at three seconds. It then records DOM measurements and a full-page screenshot; diagnostic runs also retain viewport screenshots. That timing does not prove every asynchronous view has settled. Measurement arrays are capped (60 overflow candidates, 20 horizontal containers, 45 small targets and 35 clipped-text candidates). Pixel values are rounded. The clipped-text detector excludes ellipsis, so a zero count did not clear the affected action labels; those findings use label dimensions and inspected PNGs.

Intentionally translated off-canvas navigation and locally scrolling table containers are not classified as document overflow. Tables on partner pay and admin employee management have horizontal scrolling containers; the audit does not establish that every far-right action was interactively reached. Horizontal table scrolling alone is not a finding. Full-page PNGs can be long; open the native PNG at actual size when assessing small labels.

Initial captures do not cover all loading, empty, error, validation, permission, language, theme or workflow states. Most dialogs, tabs, filters, table-scroll interactions, the complete booking/payment flow, mobile keyboard, zoom, keyboard traversal and screen readers remain unverified. The preparation file’s state suggestions and `execution: not run` metadata are historical preparation fields; executed coverage is the result data and named matrix states. Runtime repairs and clean reruns are needed for X01/X02 before those pages can receive complete layout assessment.
