## Context

Part of the owner-approved avatar feature (batch item 5). iOS has **no avatar UI** — verified
2026-07-30: `CleansiaCustomer/Sources/Features/Profile/ProfileTab.swift:261-311` (`HeroGradient`)
renders an initials-only circle (`:268-272`, `:277-283`), and there is no photo picker on
`EditProfileView.swift`. Removal is likewise absent.

**Held** until T-0446 lands *and* the owner confirms the `mobile-spec-redump` bundle. The Swift client
is generated by `scripts/generate-api-clients.sh` from
`src/cleansia_android/openapi/customer-mobile-api.json` into the **gitignored** `CleansiaCustomerApi/`
(`src/cleansia_ios/openapi/README.md:13`, `src/cleansia_ios/.gitignore:15`), so the field appears only
after the spec is re-dumped and the generator is re-run.

> **Known trap, verified on this machine:** the checked-out `CleansiaCustomerApi/` is **stale** — its
> `Models/CreateOrderCommand.swift` has neither `specialInstructions` nor `accessInstructions`, both of
> which are in the spec. **Always run `./scripts/generate-api-clients.sh` before concluding a field is
> missing.** T-0440 carries the same note.

## Acceptance criteria

_(PM floor; the `US-user-avatar` analyst panel finalizes)_

- [ ] **AC1** — Given a signed-in customer with a photo, When the profile tab renders, Then
      `HeroGradient` shows the image in place of the initials; with no photo, Then the initials circle
      exactly as today. The hero geometry (72pt circle, 3pt white-35% stroke, the top-anchored column
      and centred edit chip) is **unchanged**. Evidence: screenshots of both states.
- [ ] **AC2** — Given the edit-profile screen, When the user taps to change the photo, Then a picker
      opens (`PhotosPicker` unless the iOS-16 floor argues otherwise — see AC6), the selection previews,
      and saving uploads it. Evidence: screenshots + a ViewModel unit test.
- [ ] **AC3** — Given a user **with** a photo, When they choose remove, Then `removePhoto = true` is
      sent and the avatar reverts to initials. Evidence: a ViewModel test asserting the flag.
- [ ] **AC4** — Given a normal profile save with no photo action, When it is submitted, Then no photo
      is sent **and** `removePhoto` is false, so the avatar survives (the `fe0c985b` regression).
      **Mutation-prove it**: the test must go RED if the code sends `removePhoto = true`
      unconditionally. Name that test in the verdict.
- [ ] **AC5** — Given the picked image, When it is encoded, Then it is downscaled/compressed to a
      stated bound before base64. Confirm the bound against the backend validator
      (`Features/Users/UpdateCurrentUser.cs:61-63`) — do not invent one.
- [ ] **AC6 (Gate 8.5 — iOS 16.4 floor smoke)** — The picker API and the async image rendering are
      **exercised on the iOS 16.4 simulator**, not only the newest runtime. This is precisely the class
      of thing the floor gate exists for (`PhotosPicker` behaviour and image-loading APIs differ across
      16/17+). Launch, navigate to profile → edit, open the picker, render the avatar. Recorded on the
      ticket.
- [ ] **AC7 (Gate 8)** — `xcodebuild build test` green for `CleansiaCustomer` on an iPhone simulator;
      SwiftFormat `--lint` 0.60.1 + SwiftLint `--strict` 0.65.0 clean. **State honestly whether the
      app-scheme tests actually compiled and ran** — a scheme that cannot be generated produces zero
      test execution, and that has been misreported as a pass before.

## Implementation notes

- **Never read or modify `src/cleansia_ios/**/Info.plist` or `**/project.yml`** — the owner's live
  Stripe key lives in the working copies. A photo picker may need a usage-description key; if so,
  **do not edit `Info.plist`** (it is xcodegen-generated from `project.yml` `info.properties`) — write
  up the required key as a note for the PM to hand to the owner, and use a scratch worktree
  (where the committed `project.yml` is key-free) if you need to prove the build. `xcodegen generate`
  is safe **only** in that scratch worktree.
- **Shared-file lane:** `CleansiaCustomer/Resources/Localizable.xcstrings` — **T-0440 writes it first**
  in this sprint. Edit only your own hunks; never `git restore` it. The working tree also carries
  uncommitted iOS changes whose set **moves between sessions** — re-read `git status` before starting
  and leave every one of them alone.
- Keep `SWIFT_EMIT_LOC_STRINGS: NO` in force; do not let a catalog re-sync produce a 33k-line
  xcstrings churn (the T-0372 lesson).
- Read `agents/knowledge/patterns-mobile.md` first.
