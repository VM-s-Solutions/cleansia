## Context

Two iOS build inputs are **gitignored, machine-owned and generated**, so `git` neither updates nor
warns about them. Both go stale the moment a pull touches `src/cleansia_ios`, and **nothing anywhere
tells you they have**:

| Artifact | Generated by | Ignored at |
|---|---|---|
| the typed Swift API clients `CleansiaCustomerApi/`, `CleansiaPartnerApi/` | `src/cleansia_ios/scripts/generate-api-clients.sh` | `src/cleansia_ios/.gitignore:15-16` |
| the Xcode projects `CleansiaCustomer.xcodeproj/`, `CleansiaPartner.xcodeproj/` | `xcodegen generate`, in **both** app dirs | `src/cleansia_ios/.gitignore:9-10` |

The `.gitignore` even says so — *"XcodeGen-generated projects (regenerate with `xcodegen generate`)"*,
*"machine-owned, never committed, never hand-edited"*. **The knowledge exists; the step does not.**

### It has now cost real time, twice, in two different ways

**1 — it broke the owner's build (2026-08-01).** The generated client was dated **Jul 25** and carried
no `accessInstructions`; `BookingInstructions.swift` had **0 references** in `project.pbxproj`, so
**new code that was on `master` was silently absent from the target**. That is the sharp part: not a
compile error pointing at the cause, but a file that simply is not in the build. *(PM verified the
**repaired** state: both artifacts now timestamp `2026-08-01 15:07`, `project.pbxproj` carries **8**
`BookingInstructions` references, and `CleansiaCustomerApi/Models/CreateOrderCommand.swift` now carries
`accessInstructions`. The pre-repair figures are the owner's own observation, recorded as reported.)*

**2 — it cost a reviewer a false conclusion, and the PM propagated it.** A reviewer read the **stale**
local client, found the field missing, and declared **T-0440** blocked on an owner client-regeneration
that does not exist as an owner step. The ticket **already carried a warning about this exact trap** at
`T-0449:32-35` and `T-0440`'s equivalent — *"the checked-out `CleansiaCustomerApi/` is stale … always
run `./scripts/generate-api-clients.sh` before concluding a field is missing"* — and it was read past
anyway. The retraction is at `status/sprint-14.md` §2.12.

**That second instance is the argument for this ticket.** A warning written on the ticket, in the
ticket that was about to hit the trap, did not prevent the trap. So the fix is not another warning.

### What this ticket is NOT duplicating

**T-0456 AC8** (already written, already the sole writer of `agents/process/shared-file-lanes.md`)
covers the *opposite* hazard: **regeneration destroying uncommitted local state** — with
`xcodegen generate` → `Info.plist` → the owner's Stripe key as its worked example, and the
discriminator *"safe when the output carries no hand-edited state"*.

**T-0456 owns the rule; this ticket owns the mechanism.** They point in opposite directions and both
are correct:

| | T-0456 AC8 | T-0474 |
|---|---|---|
| Says | *don't regenerate over uncommitted state* | *do regenerate after a checkout* |
| Scope | the class, in the process doc | the iOS instance, as a runnable step |

**And the two collide on exactly one command.** `xcodegen generate` is *both* the step this ticket wants
to prescribe *and* the command T-0456 AC8 names as destructive — because it wipes the owner's
working-tree-only Stripe key. **That collision is why `depends_on: [T-0475]`** (see the sequencing note).

## Acceptance criteria

- [ ] **AC1 — a single command brings a fresh checkout to a buildable iOS tree.** Given a `git pull`
      touching `src/cleansia_ios`, When the prescribed step is run, Then **both** generated artifacts are
      current: the API clients regenerated from the committed specs, and both `.xcodeproj`s regenerated.
      Evidence: the command, run from a stale tree, with before/after state recorded (file timestamps,
      or the presence of a newly-added source file in `project.pbxproj`).
- [ ] **AC2 — a stale artifact is DETECTABLE, not merely fixable.** The step's value is halved if
      someone has to remember to run it. State what makes staleness visible: a git hook, a build-phase
      check, a `make`-style target, a documented check, or an explicit "nothing — it is a manual
      runbook step" with the reason. **The T-0440 incident is the test case: would this mechanism have
      stopped a reviewer reading a Jul-25 client and concluding a field was missing?** Answer that
      question in `## Review`, in those words.
- [ ] **AC3 — enforcement is TIERED, per ADR-0032 D2.** If the change adds anything that *claims* to
      guard staleness, it declares `**Enforced by:** <named enforcer> — <tier token>` from
      `process/enforcement.md:109-130`. A git hook is **not** T1-CI (hooks are local, uninstalled by
      default, and not in `.github/`); calling one a gate would be exactly the mis-pricing ADR-0032
      exists to stop. **`(guidance — no gate)` is an honest and acceptable answer here.**
- [ ] **AC4 — the two legs are sequenced, and the destructive one is gated.** The
      **`generate-api-clients.sh`** leg is safe today — its output carries no hand-edited state, which is
      T-0456 AC8's own discriminator — and **may ship first**. The **`xcodegen generate`** leg **must not
      be prescribed or automated until T-0475 has landed and the owner has supplied their xcconfig
      values**, because today it wipes the owner's Stripe key **on every run**. Evidence: the sequencing
      stated in the doc/script itself, not just in this ticket.
- [ ] **AC5 — the runbook lives where an agent will actually hit it.** Not only in a ticket. Candidates:
      `src/cleansia_ios/openapi/README.md` (which already documents the client regen at its
      §"Regenerate"), a top-level iOS README, or `agents/knowledge/patterns-mobile.md`. **Name the home
      and say why.** *(Note: `patterns-*.md` is a PM-ruled shared-file lane — check the lane list in
      `INDEX.md` before writing to it.)*
- [ ] **AC6 — the false-conclusion failure mode is written down next to the step.** The reader must be
      told the **symptom**, not just the remedy: *"a field that is in the committed spec but missing from
      your local client means your client is stale, not that the backend lacks it"* and *"a source file
      with zero `project.pbxproj` references is not in the target — it will not compile in, and you will
      get no error saying so."* Both are the observations that actually cost time. Evidence: the text.
- [ ] **AC7 (Gate 0.5)** — Whatever is shipped is **executed**, not just written: run it against a
      deliberately-stale tree and record what changed. **Leg 2:** a script that no-ops because everything
      was already current is a **non-run** — force the stale state first. **Leg 3:** if the `xcodegen`
      leg could not be exercised because T-0475 has not landed, **say so** rather than reporting a
      partial run as complete.

## Out of scope

- **Committing the generated artifacts.** They are gitignored by deliberate design and
  `openapi/README.md` says *"never committed, never hand-edited"*. Do not re-litigate that.
- **The Android/web regeneration story.** Android's Kotlin client generates at Gradle build time (so it
  cannot go stale the same way) and the web NSwag regen is an **owner-only** manual step with its own
  guard (T-0439). This ticket is the iOS instance.
- **The `shared-file-lanes.md` rule** — T-0456 AC8, already written, different direction. **Do not edit
  that file from this ticket**; T-0456 is its sole writer.
- **`refresh-mobile-spec.sh`** (`src/cleansia_ios/scripts/`). Refreshing the **spec** is a different
  operation from regenerating **from** the spec, and the spec is a committed artifact the owner
  re-dumps. Do not fold it in.
- **Moving the Stripe key** — that is **T-0475**, and this ticket depends on it.

## Implementation notes

**Panel: none — no new behaviour and no new decision.** This makes an already-documented regeneration
step reliably runnable. The one judgement call — *what mechanism, and what tier does it honestly claim*
— is carried as **AC2 + AC3** rather than sent to a panel. **If the implementer reaches for a git hook,
ADR-0032 D2 applies**: declare the tier honestly rather than describing a local hook as a gate.

**Sequencing, stated plainly because getting it backwards is worse than not doing it:**

```
T-0475 (secrets → gitignored xcconfig)   ← must land, AND the owner must drop their values in
   └─> T-0474 xcodegen leg               ← only now is "regenerate after every pull" safe
T-0474 generate-api-clients leg          ← safe today, independent, may ship first
```

Prescribing `xcodegen generate` as a post-pull habit **before** T-0475 lands would convert an occasional
key loss into a loss on **every single pull**. That is a strictly worse outcome than the stale-project
problem being solved. **If the two are being implemented together, land T-0475's AC2 first.**

**Do not open the working-tree `project.yml` or `Info.plist`** — the owner's live key is in them.

**Cheap and worth including:** `src/cleansia_ios/openapi/README.md` §"Regenerate" already lists the
client command. Extending that section is the lowest-friction home for the client leg (AC5) and it is
the file a reader is already in when they ask this question.
