## Context

Once **T-0493** waives the surcharge server-side, the booking flow still shows the customer
**"Express +20%"** and **"Express surcharge (+20%)"** on the summary — PM-verified strings on all
three clients:

| Client | Strings |
|---|---|
| Android | `values/strings.xml:560` `booking_slot_express` = *"Express +20%"*; `:677` `booking_summary_express_surcharge` = *"Express surcharge (+20%)"* |
| iOS | `Localizable.xcstrings` — the same two keys, same English |
| Web | `apps/cleansia.app/.../en.json:762` `slot_express`; `:764` `express_surcharge_label` = *"Express slot (+20%)"* |

**A Plus member whose surcharge was waived would see a +20% label and a total that does not include
it.** That reads as a bug to the customer and it hides the perk they are paying for at the exact
moment it pays off — which is the one moment it is worth showing.

**And the quota needs a surface.** A metered perk the customer cannot count is a support ticket
waiting to happen: *"I thought I had a free one."* T-0511 AC7 specifies the field; this ticket renders
it.

## Acceptance criteria

- [ ] **AC1 — a waived express booking shows the waiver, not the surcharge.** The slot chip and the
      summary line reflect that the member pays no surcharge — struck-through, "included with Plus", or
      whatever the copy from T-0513 AC1 supports. **The number on screen must equal the number
      charged.** Evidence: a screenshot per client for a waived member.
- [ ] **AC2 — a member with no quota left sees the surcharge, and sees WHY.** "You've used your free
      express booking this month" beats a silent +20%. Evidence: a screenshot per client.
- [ ] **AC3 — a non-member's flow is byte-for-byte unchanged.** This is a regression risk on the most
      valuable screen in the product. Evidence: the non-member screenshot per client, plus the
      existing tests still green.
- [ ] **AC4 — the remaining count is read from the API field T-0511 AC7 specifies, never computed on
      the client.** A client that counts the member's own orders will disagree with the server the
      first time an order is cancelled. Evidence: the binding at file:line, on each client.
- [ ] **AC5 — the NSwag clients are regenerated by the OWNER before frontend work starts.**
      `manual_steps: nswag-regen` (`CLAUDE.md` — agents never run `npm run generate-*-client`).
      **Hold this ticket until the owner confirms.** Evidence: the owner's confirmation in the log.
- [ ] **AC6 — five locales on every new or changed string**, en/cs/sk/uk/ru, on all three clients.
      Evidence: the key-by-key parity diff.
- [ ] **AC7 — the copy matches T-0513's canonical sentence.** Not a fourth wording. Evidence: the
      citation.
- [ ] **AC8 — shared-file lanes respected.** `Localizable.xcstrings` and the Android `values*` bundles
      are serialized lanes (`sprint-15.md` §3). Evidence: the lane check at dispatch.
- [ ] **AC9 — each client's existing test target stays green**, and the facade/viewmodel change carries
      a spec. Evidence: the runs.
- [ ] **AC10 (Gate 0.5 leg 3)** — the AC evidence is largely visual; **no leg-1 mutation proof is
      required for the screenshot ACs**. State which claims are reads, which are runs, and what was not
      checked.
