## Context

The mobile half of the payout-details change (**T-0517** ADR → **T-0518** schema → **T-0519**
contract). Android and iOS run **in parallel** off the same locked contract, per
`process/ticket-lifecycle.md`.

A cleaner onboarding on their phone must be able to give the platform somewhere to pay them. Today
that is one IBAN text field validated as `Length(15,34)`.

## Acceptance criteria

- [ ] **AC1 — the generated clients are regenerated by the OWNER before work starts.**
      `manual_steps: nswag-regen`. **⚠️ iOS additionally requires the T-0475/T-0474 toolchain step** —
      `generate-api-clients.sh` + `xcodegen generate`, and per the project memory **`xcodegen generate`
      rewrites `Info.plist` from `project.yml` and wipes the owner's working-tree Stripe key.**
      **T-0475 has landed (the gitignored `Config/Local.xcconfig` exists); the owner must have entered
      their values before any iOS instance runs xcodegen.** Evidence: the confirmation in the log.
- [ ] **AC2 — parity: the two platforms present the same field set and the same rules.** Per ADR-0018
      (iOS design-parity principle). Evidence: the screenshot pair.
- [ ] **AC3 — a cleaner can enter and save the CZ field set on each platform, and it round-trips.**
      Evidence: a screenshot pair plus a ViewModel/view-model test per platform.
- [ ] **AC4 — every server error key renders as translated text on each platform**, under **that
      platform's** error namespace (the prefix differs per client — project memory). Evidence: a
      screenshot of each error state per platform.
- [ ] **AC5 — client validation MIRRORS the server, it does not replace it.** Evidence: the rule-by-rule
      comparison against T-0519's validators.
- [ ] **AC6 — the field is not written to logs or crash reports on either platform.** Sprint-14's
      T-0457/T-0470 findings apply on the client too, and **DEV currently has no error tracking at all**
      (T-0500) — **if Q-OBS-01 turns Sentry on, an unmasked account number in a breadcrumb goes to a
      third party.** Evidence: the check per platform.
- [ ] **AC7 — five locales on every new string** on both platforms. Android `values*/strings.xml` ×5;
      iOS `Localizable.xcstrings` ×5. Evidence: the parity diff.
- [ ] **AC8 — shared-file lanes respected.** The partner `Localizable.xcstrings` and the partner
      `values*/strings.xml` bundles are serialized lanes (`process/shared-file-lanes.md`,
      `sprint-15.md` §3). Evidence: the lane check at dispatch.
- [ ] **AC9 — the SECURITY gate runs.** `security_touching: true`. Evidence: the security verdict.
- [ ] **AC10 — each platform's test target is green**, and iOS runs all three schemes (project memory:
      `CleansiaCoreTests` runs under neither app scheme; run `CleansiaCore` from the **package**
      directory). **iOS lint order: swiftformat then swiftlint** — a red "SwiftLint" is often
      SwiftFormat. Evidence: the runs.
- [ ] **AC11 (Gate 0.5 leg 3)** — the AC evidence is largely visual; **no leg-1 mutation proof for the
      screenshot ACs.** State what was read vs run.
