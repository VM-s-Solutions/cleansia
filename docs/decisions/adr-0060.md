# ADR-0060 — Money figures in copy come from the market, not the translation: a rule figure is a per-currency column, a marketing claim is a per-country column, a currency statement is the market's code, and a locale string never states an amount

- **Status:** `accepted` — **2026-09-13**, after the architect panel's challenge round and the
  implementation lanes (T-0711 backend, T-0713 admin web, T-0715 web copy, T-0717 Android copy,
  T-0719 iOS copy). Where the tree departs from the draft, §Consequences says so.
- **Date:** 2026-09-13
- **Supersedes:** —. **Amends one sentence of shipped reasoning, not an ADR:** `BookingPolicy`'s
  former `NoShowCreditCzk` doc comment ("Deliberately a CZK scalar … a per-currency amount needs
  per-market copy first") — this ADR *is* the per-market copy, so the scalar's stated reason for
  existing is discharged and the scalar is gone. ADR-0025 D3 (the closed push loc-arg allowlist) is
  **not** reopened — see D1.
- **Superseded by:** —
- **Builds on:** ADR-0058 (`MarketListItem` is the wire the figures ride), the `Currency.LoyaltyPointsDivisor`
  precedent (an authored per-currency money number, null = fail closed, admin currency form) and the
  `CountryConfiguration.RefundStripeFixedFee` precedent (a number in the country's `DefaultCurrencyCode`).
- **Applies to:** `Currency`, `CountryConfiguration`, `CancelUnfilledOrders`, the admin currency and
  country forms, the customer web locale files + `legal-pages` + `home/rules`, both mobile customer
  apps' string catalogues (and the iOS partner catalogue's copy of one push key),
  `agents/tools/check-booking-policy-parity.mjs`
- **Owner ruling (2026-09-12):** R2 — *"Rewrite per market, I mean that it'll depend on region, not
  per translation. even if now we launch only CZ, but it doesn't mean that we can forget about
  expansion."*

> **One decision:** where a money figure that appears in customer copy is *authored*, and the rule
> that a locale string carries a placeholder rather than the figure. The three groups the scout found
> (rule figure / marketing claim / currency statement) are three *sources* under one rule, not three
> decisions — the placeholder convention and the checker that enforces it are shared.

---

## Context (the tree before this programme, verified)

Exactly **six** customer-facing copy keys carried a currency figure or a currency statement. Everything
else money-shaped is a percentage, an hour count or a point count.

| # | Group | Key(s) | Surfaces | Was backed by |
|---|---|---|---|---|
| a1 | rule figure | `pages.home.rules.we_cancel_value` (web) · `notification_order_no_cleaner_refunded_body` (Android) · `push.order.no_cleaner_refunded.body` (iOS, customer + partner catalogues) | 250 CZK/Kč ×5 locales ×3 | `BookingPolicy.NoShowCreditCzk = 250m` — paid by `CancelUnfilledOrders` **only on a platform-default-currency order**; failed closed elsewhere and sent the plain `order.cancelled` push |
| b1 + b2 | marketing claim | `booking_trust_insured` ("Insured up to 1M CZK") · `help_faq_a3` ("…up to 1,000,000 CZK per booking") | Android + iOS only | **nothing** — no constant, no field, no docs line |
| b3 | marketing claim | `home_seasonal_subtitle` ("Window + upholstery combo — +450 CZK this month") | Android + iOS only | **nothing** — a static card, no date gate, no catalogue link; "spring" and "this month" are false most of the year in every market |
| c1 | currency statement | `terms_page.section3_text` ("Prices are displayed in CZK…") | web, SSR `terms` route, draft-flagged | nothing |
| c2 | currency statement | `pages.order.wizard.catalogue_changed_for_country` | web | already market-agnostic — **unchanged** |

The parity checker read `NoShowCreditCzk` off the C# declaration by regex and pinned that every locale
of the three a1 keys **contained the bare integer 250**. E-mail templates carry no literal amount and no
currency word — nothing to do there. The push loc-arg allowlist is closed `{orderNumber, count}`
(ADR-0025 D3), so a push body cannot interpolate an amount.

## Decision

### D0 — The rule: a locale string never states a money figure or a currency name

A customer-facing string may carry `{{amount}}` / `{{currency}}` (web ngx-translate), `%1$s`
(Android), `%1$@` (iOS) and **nothing else that is money**. The client formats the value with the
**market's** currency (ADR-0058 D4 precedence) through the one shared formatter each client already
has (`formatMoney(value, currencyCode, locale)`, `formatOrderPrice(amount, currencyCode)`,
`OrdersFormat.price(_, currencyCode:)`). A string with a literal figure or currency word is a defect
the checker fails (D4). Percentages, hours and point counts are **not** money and keep their literals
(the checker keeps pinning them to `BookingPolicy`).

### D1 — The rule figure (a1): `Currency.NoShowCredit`, authored per currency; the pushes stop stating a number

- **`Currency.NoShowCredit` — `decimal?`, `HasPrecision(18,2)`, `SetNoShowCredit(decimal?)`**, beside
  `LoyaltyPointsDivisor`. Null = **no apology credit in this currency** (fail closed, log, plain
  `order.cancelled` push — the branch `TryIssueApologyCreditAsync` already had). Seeded CZK = 250;
  EUR, PLN, GBP, USD = null. Authored on the admin currency form (`CreateCurrency` / `UpdateCurrency`,
  `GreaterThan(0)` when set → `MustBePositive`; null is legal on an active market).
- **`BookingPolicy.NoShowCreditCzk` is deleted.** `CancelUnfilledOrders` reads
  `order.Currency.NoShowCredit` (the order query includes the currency); the "only in the default
  currency" guard became "only when the order's currency has a figure" — the same shape, one hop
  shorter, and it now pays a EUR apology in EUR into the customer's **EUR** credit account (created if
  absent) the day an admin sets one. A null figure is logged at **Warning**, not Error — it is a legal
  authored state. Owner ruling 2026-09-06 (fail closed, never convert) is preserved exactly: nothing
  scales from another currency.
- **Rejected — `CountryConfiguration.NoShowCredit`.** The credit lands in a `CreditAccount` keyed by
  *currency*; SK and DE would carry the same EUR number twice and could drift; the job that pays it
  has an order and a currency, not a country.
- **Rejected — keep the scalar and vary only the copy.** Leaves every non-CZK market with no apology
  credit and a rules card that must say so; the scalar's own doc comment said it existed only because
  per-market copy did not.
- **Not an activation gate.** `ActivateCurrency` refuses without a loyalty divisor; it does **not**
  refuse without a no-show credit — a market with no apology credit is a valid product state, and the
  copy has a no-figure variant for it. Recorded so nobody adds the gate by symmetry.
- **Web copy:** `we_cancel_value` = "Everything back + {{amount}} credit" (five locales), `amount`
  formatted by `RulesComponent` from `MarketListItem.NoShowCredit` in the market's currency
  (`formatMoney`); when the credit is null, zero or there is no market the card renders
  **`we_cancel_value_refund_only`** ("Everything back") — a second key, not an empty placeholder.
- **Push copy (Android + iOS customer catalogues, and the iOS partner catalogue's copy of the key):**
  the body states the credit **without a figure** — *"…refunded in full, plus a credit towards your next
  booking"*. The figure is on the credit screen and the order detail, where the amount arrives with
  its currency. **Rejected — `amount` joins the loc-arg allowlist.** It reopens ADR-0025 D3 for one
  key, and — the deciding point — a loc-arg is a string the *server* formats, and the server has no
  device locale to format money in ("250 Kč" vs "250,00 Kč" vs "CZK 250"); every other money figure
  on the mobile apps is formatted on the device from a number and a code. The owner's 2026-09-06
  ruling is that the credit be **announced explicitly** as different news from a plain cancellation;
  the owner's own wording of that news — *"here is all your money back plus credit towards the next
  one"* — carries no figure. The distinct push key and its distinct copy survive; only the digits go.
  (Q-MARKET-04 carries the wording to the owner for the record.)

### D2 — Marketing claims (b): one per-country column for the insurance ceiling; the seasonal card is deleted

- **Count decides the shape:** one marketing fact with a figure (the insurance ceiling, rendered
  twice) and one false sentence. One fact is a **column**, not a table:
  **`CountryConfiguration.InsuranceCoverageAmount` — `decimal?`**, `HasPrecision(18,2)`, a number in
  the country's `DefaultCurrencyCode` (the `RefundStripeFixedFee` precedent),
  `UpdateMarketContent(decimal?)`. Null = the no-figure variants render (`booking_trust_insured_no_figure`
  = "Insured"; `help_faq_a3_no_figure` = "…covered by insurance." — the home tab's existing
  `home_trust_insured` already had no figure). Per **country**, not per currency: an insurance policy
  is written per jurisdiction (SK and DE will not share a ceiling because they share EUR).
- **Editor:** admin, rarely. `CountryConfiguration` had **no** admin writer; this ADR adds the
  **smallest** one: `PUT api/AdminCountry/{countryId}/market-content` →
  `UpdateCountryMarketContent.Command(CountryId, decimal? InsuranceCoverageAmount)` (`>= 0` when set;
  `CanUpdateCountry`; rate-limited; route-vs-body id check), refusing `country.configuration_missing`
  when the country has no configuration row (creating one needs a currency, a language and a VAT rate
  — not this command's business). Read: `CountryDetailDto` gained `InsuranceCoverageAmount` and
  `HasConfiguration`; the admin country form shows the field under a "Market" heading, disabled with
  a hint when the configuration row is missing, and saves it with its own PUT after the country update.
  **Rejected — a `MarketContent` table with a key/value or a per-locale text field.** One figure; a
  table is a content-management system for a sentence. **Rejected — the figure in
  `LegalRequirementsJson`.** Opaque, no reader, no type.
- **Customer wire:** `MarketListItem.InsuranceCoverageAmount` (ADR-0058 D1). The mobile trust badge
  and the FAQ format it with the market's currency — inside a booking the **address country's** market
  figure when that country is listed (ADR-0058 D4 rule 1), otherwise the chosen market's; an address
  in a country the directory does not list renders the no-figure variant.
- **The seed leaves the figure null.** The previous "1 000 000 CZK" claim had no backing and is not
  re-seeded; the badge and FAQ read "Insured" until the owner enters the real CZ policy ceiling on
  the country form (Q-MARKET-02).
- **b3 — the seasonal card is deleted** on both apps (`SeasonalCard` in `HomeTab.kt`, the section in
  `HomeSecondarySections.swift`, their `home_seasonal_*` strings ×5). **Rejected — a per-market
  "seasonal offer" content field.** There is no promotion behind the sentence: no package, no date, no
  discount, nothing in the backend. Building a per-market content field for it would make a false
  claim configurable in more markets. When a real seasonal promotion exists, it is a promo code or a
  package with a price row and is rendered from that. (Proportionality rule: do nothing → delete.)

### D3 — Currency statements (c): the market's code, interpolated

- **c1** `terms_page.section3_text` = "… Prices are displayed in {{currency}} and are the final amount
  payable." — `currency` = `MarketListItem.CurrencyCode` (ADR-0058), passed by the `terms` component
  through the legal-document component's `sectionParams`. The `terms` route is SSR; the market cookie
  makes the server render right. The page stays draft-flagged (`review_notice`); this ADR changes the
  unit, not the legal wording. **When no market resolved** (ADR-0058 D3's failure shape) the paragraph
  renders **`terms_page.section3_text_no_market`** — the same sentence with "the currency of the
  country you are booking in" in the unit's place, five locales, no empty placeholder in a legal
  paragraph. The draft had it reuse `pages.order.wizard.catalogue_changed_for_country`; that key opens
  with *"Some of your selection is not offered at this address, so it was removed"*, which is not a
  legal-page sentence, so the web lane added the key (A8 below, taken after all). The rules card in
  the same state renders `we_cancel_value_refund_only`, which under-promises and is still true. The
  contact phone on the privacy page is a CZ fact, not money — out of scope, reported.
- **c2** unchanged. **c3** (error strings naming "currency") unchanged — generic wording, no figure.
- The design-language honesty table (`agents/knowledge/design-language.md` §6.2) quoted "500 Kč" and
  "Plus 199 Kč/mo" as examples; rewritten so the catalogue does not teach the form this ADR forbids.

### D4 — The parity checker keeps working by pinning the *absence* of a figure and the *presence* of the placeholder

`check-booking-policy-parity.mjs`:

- The `NoShowCreditCzk` read and the three `amountsIn(...).includes(noShow)` blocks are **gone**. The
  figure is data now; there is no code authority to pin copy to.
- **Per surface, `pinPlaceholderCopy`:** the value must carry its placeholder where one is expected,
  and after the placeholder slot is stripped (`{{x}}`, `%1$s`, `%1$@` — `amountsIn()` would otherwise
  read the `1` in `%1$s` as an integer) it must contain **no integer and no currency word**
  (`CZK|Kč|EUR|€`). Pinned: web `we_cancel_value` (`{{amount}}`), `we_cancel_value_refund_only`,
  `terms_page.section3_text` (`{{currency}}`), `terms_page.section3_text_no_market`; Android
  `notification_order_no_cleaner_refunded_body`, `booking_trust_insured` (`%1$s`),
  `booking_trust_insured_no_figure`, `help_faq_a3` (`%1$s`), `help_faq_a3_no_figure`; iOS
  `push.order.no_cleaner_refunded.body`, `booking_trust_insured` (`%1$@`), `help_faq_a3` (`%1$@`) and
  their `_no_figure` twins — every locale of each. The self-test carries a "literal figure crept back
  into a placeholder key" drift case per surface.
- **The checker was edited per surface, in the ticket that changed that surface's copy**, so the
  branch was green at every commit. The interim between the backend ticket (which deleted the
  constant) and the last copy flip used a **checker-local constant** —
  `INTERIM_NO_SHOW_CREDIT_CZK = 250` — for the three still-literal pins, never a read of the seed SQL;
  the last flip deleted it, and the tree carries no trace of it. **Rejected — reading the CZK row's
  `NoShowCredit` out of `insert_seed_data.sql` by regex:** the Currencies block is a multi-row
  `VALUES` list, a regex on it is fragile, it adds a workflow path trigger that is deleted again three
  tickets later, and the thing the interim pin guarded was only that the three surfaces still *agreed
  with each other* — a constant does that.
- The workflow's path triggers are **unchanged** throughout (no `Currency.cs`, no seed).

## Alternatives considered

| # | Alternative | Why not |
|---|---|---|
| A1 | Per-market **locale files** (`cs-CZ.json`, `sk-SK.json`) | Locale × market is a product; the owner's ruling is exactly that money is *not* a translation concern. |
| A2 | A `MarketContent` table (key/value per country) | One figure today; the second caller does not exist (D2). |
| A3 | `amount` as a push loc-arg | D1 — the server cannot format money for a device locale; ADR-0025 D3 stays closed. |
| A4 | Keep `BookingPolicy.NoShowCreditCzk` + per-market copy that omits the figure off-CZK | Leaves non-CZK markets without the credit forever and the scalar's own reason gone (D1). |
| A5 | Per-market seasonal content | A false sentence made configurable (D2). |
| A6 | Drop the no-show pin from the checker entirely | A literal "250" typed back into a placeholder key by a translator would pass; the inverse pin costs one regex (D4). |
| A7 | Interim checker authority = regex over the seed SQL | Fragile on a multi-row `VALUES`; a workflow trigger added and removed within three tickets; the interim only needed the three surfaces to agree — a checker-local constant did that (D4). |
| A8 | Reuse `catalogue_changed_for_country` for the terms page's no-market state (the draft's D3) | Rejected at implementation, the other way round: that key is a wizard notice about a trimmed basket, not a legal sentence. A dedicated `terms_page.section3_text_no_market` was added and pinned (D3). |

## Consequences

- **Schema:** `Currencies.NoShowCredit numeric(18,2) NULL`; `CountryConfigurations.InsuranceCoverageAmount numeric(18,2) NULL`;
  `Initial` regenerated (with ADR-0058's `Countries.IsoAlpha2` and ADR-0059's tables, one regen per
  backend ticket; DEV drop at deploy).
- **Admin:** currency form + one field (`noShowCredit`, blank → absent on the wire → null); country
  form + one field + one PUT; `AdminCurrencyDetailDto` / `AdminCurrencyListItem` + `noShowCredit`
  (`CurrencyListItem` / `CurrencyDetailDto`, which travel on order rows, untouched).
- **Copy:** six keys rewritten ×5 locales ×(1–3 platforms) + five new keys (`we_cancel_value_refund_only`,
  `terms_page.section3_text_no_market`, `booking_trust_insured_no_figure`, `help_faq_a3_no_figure` on
  both mobile apps); two `home_seasonal_*` keys and one card deleted per mobile app; the customer iOS
  catalogue now contains no `CZK|Kč|EUR|€` anywhere.
- **Docs:** `/product/business-rules#money-constants` — the no-show credit is "authored per currency;
  CZK 250; a currency with none pays none and sends the plain cancellation push"; the "250 CZK"
  literals on that page and the cancellation flow became that sentence; `/product/features` names the
  insurance figure as per-country content.
- **Deviations from the draft, recorded:** the terms page's no-market state is a new key, not the
  reused wizard sentence (D3, A8); the Android and iOS placeholders are `%1$s` / `%1$@` (the draft
  wrote `%@`); the checker strips the placeholder slot before the no-integer check (D4).
- **Role card:** none new — `Currency` and `CountryConfiguration` gain a field each; no new
  collaborator. The market directory that carries both figures to the clients has its own card
  (`/domain/roles/market-directory`).

## How a reviewer verifies compliance

1. `grep -rn "NoShowCreditCzk" src/ agents/tools/` → 0 hits; `Currency.NoShowCredit` is read by
   `CancelUnfilledOrders` and `GetMarkets` (plus the admin currency mappers) and nothing else.
2. Integration test on real Postgres (`CancelUnfilledOrdersApologyCurrencyTests`): a CZK order with no
   cleaner is cancelled, refunded and credited 250 with `order.no_cleaner_refunded`; a EUR order (EUR
   `NoShowCredit = null`) is refunded, not credited, `order.cancelled` sent, warning logged; an order in
   a currency with an authored figure is credited that figure into the account in **that** currency.
3. `node agents/tools/check-booking-policy-parity.mjs` passes and its self-test's drift cases fail on
   a locale that states "250" or "250 Kč" in a placeholder key.
4. `grep -rn "CZK\|Kč\|EUR" apps/cleansia.app/src/assets/i18n/*.json customer-app/src/main/res/values*/strings.xml CleansiaCustomer/Resources/Localizable.xcstrings`
   → hits only in currency-name lookup tables and the error strings named in c3 (the iOS customer
   catalogue has none at all).
5. `PUT api/AdminCountry/{id}/market-content` on a country with no configuration answers
   `country.configuration_missing`; `CountryDetailDto.insuranceCoverageAmount` round-trips
   (`UpdateCountryMarketContentValidatorTests`, `MarketDirectoryRouteTests`).
6. Both mobile apps: no `SeasonalCard` / `home_seasonal_*` symbol; the trust badge and FAQ render the
   no-figure variant when `insuranceCoverageAmount` is null (`ConfirmStepViewModelTest`,
   `HelpSupportViewModelTest`, `MarketCopyStringsTest`; `MarketCopyTests`).

## Challenge / Defense / Verdict

### Challenge (Architect, challenger mode, 2026-09-13)

1. **D4's interim authority read the seed SQL by regex** and added/removed a workflow trigger within
   three tickets, to guard a property (three surfaces agree) that a checker-local constant guards
   equally. *Conceded:* constant, deleted by the last flip; workflow untouched.
2. **D3 left a legal paragraph with an empty `{{currency}}`** in the no-market failure shape ADR-0058
   D3 defines. *Conceded:* a market-agnostic sentence renders instead.
3. **D1 — pushes without the figure.** Challenged on whether dropping digits from the lock-screen
   line weakens the 2026-09-06 ruling. *Defended, stands:* the ruling's own wording carries no
   figure; the distinct key and copy survive; the amount is on the credit screen with its unit; the
   alternative reopens ADR-0025 D3 for a server-formatted money string. Carried to the owner as
   Q-MARKET-04 for the record, not as a blocker.
4. **D2 — deleting the seasonal card.** Challenged as scope creep (copy programme deletes a UI
   section). *Defended, stands:* the card states a money figure that no rule, package or promotion
   backs, in every market; R2 says such figures are per-market data, and there is no datum. The
   deletion is the proportional form of "do nothing".

### Defense

Items 1–2 conceded and revised; 3–4 defended and unchanged.

### Verdict

*(Lead mode, 2026-09-13.)*

| # | Ruling |
|---|---|
| C1 | **RESOLVED** — the constant lived in the checker for the three interim commits and is gone; the workflow triggers never moved. |
| C2 | **RESOLVED, with one correction at implementation** — the concession named the wizard's `catalogue_changed_for_country` as the fallback sentence; read in full it is a notice about a trimmed basket, so the web lane added `terms_page.section3_text_no_market` instead and the checker pins it. The property the challenge asked for — no empty placeholder in a legal paragraph — holds either way. |
| C3 | **DEFENSE UPHELD** — the pushes name the credit and not the figure; Q-MARKET-04 records the owner's option to reopen ADR-0025 D3. |
| C4 | **DEFENSE UPHELD** — the seasonal card is gone from both apps with its strings. |

**Consensus reached; zero blocking challenges.** Status `accepted`. The rule the panel attacked — a
locale string carries a placeholder, the figure is authored per currency or per country and formatted
on the client in the market's currency, the checker pins the absence — survives whole; the one
deviation (a dedicated no-market key for the terms page) is recorded above.
