# ADR-0077 — Every cleaner marks done before a crew completes the job

- **Status:** `accepted` — Mike's ruling of 2026-10-26, clarified 2026-10-27.
- **Date:** 2026-10-27
- **Applies to:** partner web, Android and iOS; both partner API hosts; automatic completion.
- **Composes with:** [ADR-0068](./adr-0068) (the seat's contract for work),
  [ADR-0071](./adr-0071) (order concurrency) and [ADR-0072](./adr-0072) (one scope per system command).

## Context

One cleaner could complete a multi-cleaner job while another was still working. Mike ruled:
*"each cleaner has to mark on his device that he's done. And then there is a shared button appears
that can be clicked by any on them"*. On automatic completion: *"If everyone marked that they're
done, but didn't click on a shared button then yes. If not then they're still cleaning"*.

The one-cleaner default stated to Mike and not vetoed keeps today's single Complete action.
On 2026-10-27 Mike explicitly chose to keep the existing after-photo and settled-payment checks
for automatic completion too.

## Decision

1. On a job with **two or more assigned cleaners**, each cleaner uses **I'm done** on their own
   device. `POST api/Order/MarkMyPartDone` stamps only their seat's
   `OrderEmployee.CompletionConfirmedAt`, only while the order is `InProgress`. The first timestamp
   wins; repeating the request keeps it. A cleaner outside the crew is refused before the job's state
   is disclosed.
2. A first mark sends `order.crew_mate_done` to the other eligible cleaners on the job, including
   those who already marked. It is push-only, with `orderNumber` for localization and `orderId` for
   opening the job; no in-app feed row is added.
3. Once **every seat still on the job** is stamped, any assigned cleaner may use the shared
   **Complete job** action. This runs the existing completion, with its contract, profile, approval,
   after-photo and payment checks. A premature Complete on a crew job is refused with
   `order.crew_not_done`, including when nobody has marked yet. The rule counts actual assigned
   seats, not `RequiredEmployees`; a job held by one cleaner keeps the ordinary single Complete.
4. If everyone marked and nobody completes, the job becomes eligible **120 minutes after the last
   mark**. The existing fifteen-minute cleanup timer processes it on a subsequent tick. Missing
   marks, an absent after photo or unsettled payment leave it `InProgress`; no administrator alert
   is added. Automatic work minutes end at the last mark, excluding the wait for Complete.
5. Mark, manual Complete and automatic completion take the same PostgreSQL order-row lock before
   reading the crew. Competing completion calls serialize; a manual call that waited for a successful
   completion returns success without repeating it. Manual and automatic completion share
   `CompleteOrder.FinishAsync`: status, receipt intent, customer notification/e-mail, applicable
   loyalty/referral effects and a pay-calculation request for every assigned cleaner. A queued pay
   calculation is not an immediate payout.

The partner web crew rows and the admin crew card show each mark's time. Customers and browsing
cleaners receive no completion timestamps. Native apps use the stamps to choose the next action;
they gain no crew-time panel. Android and iOS keep their lifecycle slide gesture, labelled
**I'm done** or **Complete job** for crew steps; solo remains **Slide to complete**.

## Consequences and limits

The action reflects the **last fetched order**. Local actions fetch again; a cleaner waiting with
the detail already open may need to reopen/reload it, follow the push, or refresh on Android to see
another cleaner's mark. No live foreground push-to-detail refresh or polling was added. The server
still refuses stale premature completion.

A cleaner who marked done **still blocks overlapping work**, and still counts as working for
Start and reminder suppression, until completion or the relevant booked window ends. This is an
unchanged residual, not a new owner acceptance of it. There is no undo, per-cleaner photo/minute
record or administrator action to mark another cleaner done.

The iOS APNs display map requires the new title/body keys already present in source in both app
catalogs. **Merged source is not an installed build.** Older TestFlight apps lack that copy and the
mark action; the new TestFlight release remains blocked by signing. Old partner builds cannot
complete a job with two or more assignees, and zero marks never qualify for automatic close. Use
updated clients or partner web for crew jobs while native releases are pending. This release dependency
stays visible alongside the post-merge DEV work; no release is claimed here.
